# Material de treino no GitHub (2024-2026) para bootstrapping das "lessons" de um bot de trading com LLM local

Contexto do pedido: bot Python (Interactive Brokers, barras de 1 min agregadas a 5 min, RSI/SMA/EMA/ATR, LLM local via Ollama — Llama3/Qwen2.5 7B — a propor BUY/SELL/HOLD) com tabela SQLite de "lessons" (regras curtas derivadas de resultados medidos, p.ex. "BUY com RSI>=70 falhou 3/20 vs base 45%"), injetando as top-3 no prompt. Pergunta: existe no GitHub material de "lessons"/treino reutilizável para este tipo de bot?

Nota metodológica: o ambiente desta pesquisa bloqueou o acesso direto a huggingface.co, hf-mirror.com, arxiv.org, ar5iv, alphaxiv, papers.cool, themoonlight.io, firstratedata.com, marketparquet.com e ta-lib.github.io; os `gh api` e o MCP do GitHub estavam limitados ao repositório da sessão. Os READMEs e ficheiros LICENSE foram lidos via raw.githubusercontent.com e páginas github.com; os dados de papers e de datasets HF vêm de resultados de pesquisa (snippets) e são assinalados como tal. Estrelas e versões são as visíveis a 2026-10-05.

## Pergunta-chave 1 — Existe algum corpus publicado de "lessons" de agentes de trading LLM importável diretamente? Se não, qual é o substituto mais próximo?

### Takeaway
Não encontrei nenhum repositório (TradingAgents, FinMem, FinCon, FinAgent, QuantAgent, ai-hedge-fund, Trading-R1) que publique um corpus reutilizável de "lessons learned"/reflexões; todos geram memória em runtime e não a distribuem. O substituto mais próximo é (a) reutilizar o *formato e o prompt de reflexão* do TradingAgents (Apache-2.0) para gerar as próprias lessons offline a partir de histórico, e (b) catálogos de regras técnicas em código (freqtrade-strategies GPL-3.0, 101 Formulaic Alphas, TA-Lib) convertidos em lessons com estatísticas medidas no próprio backtest.

#### 1. Memória/reflexão dos frameworks de agentes LLM

- **TradingAgents (TauricResearch)** — licença Apache-2.0 confirmada no ficheiro LICENSE — [LICENSE](https://raw.githubusercontent.com/TauricResearch/TradingAgents/main/LICENSE); página GitHub mostra ~109.8k estrelas e 21.1k forks — [github.com/TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents); README indica v0.6.0 (outubro 2026), suporte a Ollama e endpoints OpenAI-compatíveis (vLLM, LM Studio, llama.cpp), análise diária e backtest em grelha ticker/data — [README](https://raw.githubusercontent.com/TauricResearch/TradingAgents/main/README.md).
- O README afirma que "Each completed run appends its decision to `~/.tradingagents/memory/trading_memory.md`", que o sistema liquida decisões cujo período de holding passou (retorno realizado e alpha vs benchmark) e que "The Portfolio Manager then reads the most recent decisions for the same ticker plus recent lessons from other tickers" — [github.com/TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents). O README **não** inclui nenhum dataset de memórias/lessons de exemplo — [README](https://raw.githubusercontent.com/TauricResearch/TradingAgents/main/README.md).
- Formato em disco (`tradingagents/memory/log.py`): cada entrada tem uma linha-tag `[trade_date | ticker | rating | raw_return% | alpha_return% | holding_days | resolved:date]`, secções `DECISION:` e `REFLECTION:`, separador `<!-- ENTRY_END -->`; `get_past_context()` injeta até 5 entradas do mesmo ticker (decisão+reflexão) mais 3 lessons de outros tickers (só reflexão); há rotação opcional `memory_log_max_entries` que apaga as resolvidas mais antigas — [memory/log.py](https://raw.githubusercontent.com/TauricResearch/TradingAgents/main/tradingagents/memory/log.py).
- Prompt de reflexão (`tradingagents/memory/reflection.py`): pede "exactly 2-4 sentences of plain prose (no bullets, no headers, no markdown)" cobrindo, por ordem, acerto direcional citando o alpha, validação da tese e uma lição concreta; inputs: decisão final, retorno bruto, alpha vs benchmark (default SPY), dias de holding (default 5 dias de bolsa); usa o `quick_thinking_llm` — [memory/reflection.py](https://raw.githubusercontent.com/TauricResearch/TradingAgents/main/tradingagents/memory/reflection.py).
- Testes do repo referem explicitamente filtragem *point-in-time* da memória (`tests/test_memory_pointintime.py`) e o campo `resolved:` existe para esse fim — [pesquisa de código](https://github.com/TauricResearch/TradingAgents) (via GitHub code search `TradingMemoryLog reflection repo:TauricResearch/TradingAgents`).

### Inferences
- O único artefacto diretamente reutilizável é o *esquema* de lesson do TradingAgents (tag com retorno/alpha/holding + reflexão de 2-4 frases, com `resolved:` para point-in-time). Mapeia quase 1:1 na tabela SQLite do bot: ticker, data, decisão, retorno, alpha, texto da lição, data de resolução. Vale a pena copiar o prompt de reflexão (Apache-2.0 permite) e corrê-lo em Ollama sobre o histórico de trades do próprio bot.
- Como ninguém publica memórias, a via mais barata para "não começar do zero" é gerar lessons sintéticas *medidas*: aplicar as regras do freqtrade-strategies / alphas 101 / padrões TA-Lib às barras de 5 min do próprio IB, medir hit-rate vs base e escrever a lesson no formato atual ("regra X: a/b vs base c%"). Isto respeita o espírito do sistema atual (regras derivadas de resultados medidos) e evita importar afirmações não verificadas.
- As licenças importam: código GPL-3.0 do freqtrade só é problema se se redistribuir o bot; usar as regras como fonte de hipóteses e reimplementar não cria obrigação. O repositório alpha101 sem licença não deve ser copiado — usar o paper (fórmulas públicas) e reimplementar.

## Pergunta-chave 2 — Que 2-3 datasets dão melhor valor para (a) semear lessons no prompt e (b) um LoRA pequeno de BUY/SELL/HOLD sobre features técnicas, treinável em GPU de consumo e importável no Ollama?

### Takeaway
Não existe no GitHub um dataset de instruções "features técnicas intradiárias → BUY/SELL/HOLD"; os datasets SFT financeiros abertos (FinGPT-Forecaster, PIXIU/FinBen stock-movement, Fin-R1, FinLoRA) são diários, baseados em texto/notícias e, no caso do FinGPT, com labels geradas por GPT-4. O melhor valor é construir o próprio dataset a partir de OHLCV 1-min aberto (p.ex. ggaddam/OHLCV-1m em HF, marketparquet free tier, FirstRate) com labels de retorno forward ajustado à volatilidade (receita do Trading-R1) e usar FinGPT-Forecaster + flare-sm-acl apenas como referência de formato e de avaliação.

### Inferences
- Para **(a) seed lessons**: nenhum dataset traz regras prontas; a melhor fonte são catálogos de regras (freqtrade-strategies, alphas 101, 61 padrões TA-Lib) *medidos no histórico IB 1-min do bot*, mais a disciplina do TradingAgents (lição só após liquidar o trade, alpha vs SPY). Um pacote inicial realista: ~30-60 lessons com contagens reais (a/b vs base) por regime (RSI extremos, cruzamentos EMA, ATR relativo), geradas por script e não pelo LLM.
- Para **(b) LoRA**: os datasets abertos não encaixam (diários, texto/tweets, Rise/Fall binário, labels GPT-4). O caminho com melhor valor é um dataset próprio: OHLCV 1-min aberto → agregação 5 min → features RSI/SMA/EMA/ATR em texto → label 3/5 classes por retorno forward ajustado à volatilidade (Trading-R1) → QLoRA em Qwen2.5-7B-Instruct (o FinLoRA e o OpenMedallion mostram QLoRA de 7-8B em GPUs de consumo/A5000 por <100 USD) → exportar adapter merged em GGUF para Ollama. `flare-sm-acl` serve como conjunto de avaliação externo de sanidade (binário, diário), não como treino.
- Fin-R1 e FinLoRA só ajudam na "literacia financeira" geral do modelo, não no sinal; InvestLM é non-commercial e 65B, inútil aqui.

## Pergunta-chave 3 — Que evidência existe de que afinar modelos 7B nestes datasets melhora decisões de trading, e quais os modos de falha (incl. leakage temporal, qualidade das labels, licenças, transferência diário→intradiário)?

### Takeaway
A evidência é modesta e toda diária: modelos 7B afinados (Ploutos-7B) sobem de ~50% (aleatório) para ~61% de acerto / MCC 0.205 no ACL18, enquanto FinMA-7B e GPT-4 zero-shot ficam perto de 50%; não há estudos que mostrem transferência para barras de 5 min. Os modos de falha documentados são memorização/look-ahead (≈37% do efeito preditivo aparente em previsão de retornos atribuído a memorização), labels geradas por GPT-4, alucinação numérica e mau desempenho em regimes laterais/voláteis.

### Cited Findings

#### Evidência de ganhos com fine-tuning

- Ploutos-7B no ACL18: 61.21% acc / 0.205 MCC vs FinMA-7B 56.28% / 0.104 e GPT-4 53.08% / 0.023; no CIKM18: Ploutos 59.89% / 0.064, FinMA 53.24% / -0.031, GPT-4 57.44% / 0.034 — [Ploutos, arXiv 2403.00782](https://arxiv.org/pdf/2403.00782) (snippet).
- Zero-shot, LLaMA-2 e GPT-4 "perform similarly to random guessing (ACC = 0.5)" em stock movement; só o fine-tuning ultrapassa — [Ploutos](https://arxiv.org/pdf/2403.00782) (snippet).
- FinMA-7B-full no FLARE: BigData22 50.5% (0-shot) / 51.5% (5-shot) vs baseline 53.0%; ACL18 51.2% / 51.1% vs 56.0%; CIKM18 49.3% / 48.7% vs 53.0% — [arXiv 2510.05151 (FinMA review)](https://arxiv.org/pdf/2510.05151) (snippet).
- Um SLM afinado (Phi-2) "outperformed GPT-4, albeit by a small margin" em previsão de movimento de ações — [Tilburg University](https://research.tilburguniversity.edu/en/publications/comparative-analysis-and-evaluation-of-slms-and-llms-for-stock-pr/); [arXiv 2412.09394](https://arxiv.org/pdf/2412.09394v2) (snippets).
- Estudo Georgia Tech "AI Trading: Evaluating LLMs for Technical Market Analysis" (GPT-4 Turbo, Claude 3 Opus, Gemini 1.5 Pro, Llama 3 70B, FinGPT): FinGPT "demonstrates competitive risk-adjusted performance due to domain-specific fine-tuning"; tarefas incluem reconhecimento de candlesticks, sinais BUY/SELL/HOLD e backtest — [arXiv 2607.15414](https://arxiv.org/pdf/2607.15414) (snippet).
- Trading-R1 (4B? tamanho não confirmado) reporta "improved risk-adjusted returns and lower drawdowns" vs modelos instruct e de raciocínio, em 6 ações/ETFs — [arXiv 2509.11420](https://arxiv.org/pdf/2509.11420) (snippet; números não acessíveis).
- FinLoRA: LoRA em Llama 3.1 8B com "4 A5000 GPUs", "<$100", +36% médio, mas em tarefas de NLP/contabilidade, não de sinal — [README FinLoRA](https://raw.githubusercontent.com/Open-Finance-Lab/FinLoRA/main/README.md). OpenMedallion-FinSentiment: QLoRA 4-bit sobre Qwen2.5-7B-Instruct para sentimento — [HF](https://huggingface.co/oyi77/openmedallion-finsentiment) (snippet).

#### Modos de falha e caveats

- Look-ahead/memorização: "A Test of Lookahead Bias in LLM Forecasts" estima que "roughly 37% of apparent predictive effect in stock return prediction is amplified by memorization" e 19% em previsões de CapEx — [arXiv 2512.23847](https://arxiv.org/pdf/2512.23847) (snippet). FinLeak-Bench/FactFin: "most published LLM-based agents fail to beat baselines once their knowledge cutoff is passed"; Lopez-Lira et al. (2025): modelos recordam preços de fecho do S&P 500 com <1% de erro dentro da janela de treino e o erro "explode" após o cutoff — [hedgefundalpha (resumo)](https://hedgefundalpha.com/education/your-llms-alpha-might-be-mere-memorization/) (snippet; página bloqueada).
- Labels: as labels do FinGPT-Forecaster são "GPT-4 generated" e o próprio README avisa que "Results inferred from randomly chosen news can be strongly biased" — [README](https://raw.githubusercontent.com/AI4Finance-Foundation/FinGPT/master/fingpt/FinGPT_Forecaster/README.md). A reflexão do TradingAgents reconhece que "a thesis spanning months may not be disproved by a week's performance" (holding default 5 dias) — [reflection.py](https://raw.githubusercontent.com/TauricResearch/TradingAgents/main/tradingagents/memory/reflection.py).
- Modos de falha dos LLMs em análise técnica: "numerical hallucination, context-window limitations, and inconsistent performance in sideways market regimes" — [arXiv 2607.15414](https://arxiv.org/pdf/2607.15414) (snippet); InvestorBench: "all models struggle in highly volatile market conditions" — [arXiv 2412.18174](https://arxiv.org/pdf/2412.18174) (snippet).
- Look-ahead em estratégias de regras: o freqtrade-strategies mantém uma subpasta `lookahead_bias` dedicada a exemplos deste erro — [tree](https://github.com/freqtrade/freqtrade-strategies/tree/main/user_data/strategies).
- Licenças restritivas: InvestLM "noncommercial license for research only" — [README](https://raw.githubusercontent.com/AbaciNLP/InvestLM/main/README.md); FinLoRA OpenMDW-1.0 e CFA/CPA não publicáveis — [README](https://raw.githubusercontent.com/Open-Finance-Lab/FinLoRA/main/README.md); freqtrade-strategies GPL-3.0 — [LICENSE](https://raw.githubusercontent.com/freqtrade/freqtrade-strategies/main/LICENSE); yli188/WorldQuant_alpha101_code, The-FinAI/FinCon, The-FinAI/InvestorBench, AbaciNLP/InvestLM e wilsonfreitas/awesome-quant **sem ficheiro LICENSE** (verificação curl raw em 2026-10-05).
- Transferência diário→intradiário: a pesquisa não devolveu nenhum estudo peer-reviewed a comparar o poder preditivo do RSI (ou outros indicadores) em 5 min vs diário; só material prático/TradingView — [resultados de pesquisa](https://quantzee.btw.so/is-rsi-still-relevant-for-nifty-intraday-trading-in-2025-a-deep-dive-into-real-market-setups). Os alphas 101 têm holding 0.6–6.4 dias e usam dados diários — [arXiv 1601.00991](https://arxiv.org/pdf/1601.00991).

### Inferences
- Ganhos de ~5-10 pontos de acerto (50%→56-61%) em classificação binária diária são o teto demonstrado para 7B; MCC ≤ 0.2 indica sinal fraco. Para 5 min, sem evidência, o mais prudente é tratar o LoRA como classificador de features (sem notícias), avaliar com walk-forward e exigir que bata uma baseline de regras simples antes de o ligar ao prompt.
- O risco de leakage para o bot é duplo: (i) o LLM base pode "conhecer" preços históricos de datasets antigos (ACL18 2014-15, DOW30 2023) — qualquer avaliação deve usar dados posteriores ao cutoff do modelo (Qwen2.5/Llama3: 2023-24) ou tickers/períodos sintéticos; (ii) lessons calculadas sem o `resolved:` point-in-time contaminam backtests — replicar o mecanismo do TradingAgents.
- Importar lessons "diárias" (alphas, estratégias freqtrade de cripto) sem as re-medir em 5 min contradiz a lógica do sistema atual; devem entrar como *hipóteses* a testar e só serem promovidas a lessons após contagens no histórico IB.

### Gaps
- Não acedi aos PDFs do Trading-R1, do estudo Georgia Tech (2607.15414), do Tilburg (2412.09394) nem do look-ahead (2512.23847); os números citados vêm de snippets de pesquisa e devem ser verificados antes de publicação.
- Não encontrei números de "binary accuracy" do FinGPT-Forecaster Llama-2-7B publicados.
- Não encontrei qualquer avaliação pública de LLMs 7B afinados em barras intradiárias (1-5 min) com BUY/SELL/HOLD; a transferência diário→intradiário permanece sem evidência.
- Não confirmei o tamanho do modelo base do Trading-R1 nem se os pesos foram publicados em HF.
